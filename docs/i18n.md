### Internationalization (i18n) and Multilingual Support in Chirp

This guide explains how multilingual support works in this KMP/Compose project, where the code lives, how startup language is applied, how to switch languages at runtime, and how to add new locales safely. It reflects the actual implementation in this repository as of now.

---

#### Key concepts and building blocks

- Compose Multiplatform resources
  - Each module can define `src/commonMain/composeResources/values/strings.xml` and per‑locale files (e.g., `values-ar/strings.xml`).
  - Access with `org.jetbrains.compose.resources.stringResource(...)` and module‑scoped generated `Res` accessors.
- LanguageManager (shared singleton)
  - Central source of truth for current language + validation of supported languages. Updates platform locale via `changeLanguage(expect/actual)` and exposes `currentLanguage` as Compose state.
- ProvideMultilingualSupport
  - Wraps `ProvideAppLanguage(languageCode)` and sets `LocalLayoutDirection` to RTL for `ar`, `fa`, `he`, `ur`, etc.
- ChirpTheme(languageCode)
  - Chooses language‑appropriate typography (e.g., Arabic‑friendly family) to ensure correct glyph rendering.
- SettingsStorage (extensible app settings)
  - Persists `AppSettings(languageCode: String?)` via DataStore. `languageCode == null` means no explicit user choice yet (first‑run).
- App gating via MainViewModel/MainState
  - Ensures the language is applied before showing the main UI to avoid flicker and ensure correct RTL/typography.

#### Startup language and gating

- `MainViewModel` loads persisted settings on init:
  - Reads `settingsStorage.observeSettings().firstOrNull()?.languageCode`.
  - If null (first‑run), picks default from `languageManager.getSupportedLanguages().first()`.
  - Calls `languageManager.setLanguage(code)` which updates the platform locale via `changeLanguage(...)` and `LanguageManager.currentLanguage`.
  - Updates `MainState` with `currentLanguage`, flips `isCheckingLanguage = false`, and sets `hasChosenLanguage = (initial != null)`.
- `App.kt` renders the UI only when `!state.isCheckingAuth && !state.isCheckingLanguage` and wraps the tree with:
  - `ChirpTheme(languageCode = languageManager.currentLanguage)` (typography)
  - `ProvideMultilingualSupport(languageManager.currentLanguage)` (CompositionLocal + RTL)

This guarantees the app launches in a consistent, language‑aware state without a visible language “flicker”.

#### First‑run Language selection flow (Auth)

- On first run (no persisted language), the Auth graph starts at the `LanguageSelection` route; otherwise it starts at `Login`.
- `LanguageSelectionScreen` lists supported codes from `LanguageManager` as radio options and uses module‑scoped resources for labels:
  - EN file: `feature/auth/presentation/src/commonMain/composeResources/values/strings.xml`
  - AR file: `feature/auth/presentation/src/commonMain/composeResources/values-ar/strings.xml`
- On confirm:
  - Persist via `SettingsStorage.setLanguage(code)`
  - Apply via `languageManager.setLanguage(code)`
  - Navigate to `Login` (or to the next appropriate auth step)

Tip: A compact language entry (e.g., globe icon) can be added to Auth screens to re‑open the Language selection screen. This is optional and can be implemented using the design system scaffolds.

#### Switching language at runtime from anywhere

- `MainViewModel.changeLanguage(code)` persists to settings and applies via `LanguageManager`. The UI recomposes because `currentLanguage` is state and platform locale changes.

Snippet:
```kotlin
fun changeLanguage(code: String) {
    viewModelScope.launch {
        settingsStorage.setLanguage(code)
        if (languageManager.setLanguage(code)) {
            _state.update { it.copy(
                currentLanguage = languageManager.currentLanguage,
                hasChosenLanguage = true
            ) }
        }
    }
}
```

#### Adding a new locale (example: French `fr`)

Repeat for each module that owns strings.

1) Create resource files
- `src/commonMain/composeResources/values/strings.xml` (base) already exists.
- Add `src/commonMain/composeResources/values-fr/strings.xml` with a 1:1 key mapping.

2) Use resources
- Continue using `stringResource(Res.string.some_key)` in Composables.

3) Typography and RTL, if relevant
- If the new language needs specific fonts, extend `typographyForLanguage(languageCode)` and add font files to the design system.
- If RTL, ensure the code is in `isRtlLanguage` (currently covers `ar`, `fa`, `he`, `ur`).

4) Validate
- Desktop run: `./gradlew.bat :composeApp:run`
- Android run/assemble: `./gradlew.bat :composeApp:assembleDebug`

#### Platform notes

- Android actual (`Language.android.kt`): sets `Locale.setDefault(Locale.forLanguageTag(code))`. Optionally, on API 33+ you can also set per‑app locales via `LocaleManager.applicationLocales = LocaleList(locale)`. This requires a Context; if you decide to add this nicety, wire a safe application context provider and keep `Locale.setDefault` for host JVM tests and Desktop parity.
- iOS actual (`Language.ios.kt`): updates `AppleLanguages` in `NSUserDefaults` to hint preferred language ordering.
- Desktop: Uses JVM locale semantics via Compose MPP resource lookup; no changes needed beyond `LanguageManager` updates.

#### Resources hygiene and pitfalls

- Keep keys in sync across `strings.xml` and localized files; missing keys fall back to base, potentially creating a mixed‑language UI.
- Use the correct module’s `Res` accessors where the strings are defined.
- Prefer `UiText` in non‑UI layers when passing text to the UI (`UiText.Resource(...)` vs dynamic strings) for safer localization.

#### Testing and validation

- Manual checklist
  - First run prompts Language selection; selecting applies immediately and persists.
  - Relaunch uses the persisted language; no flicker on first frame.
  - RTL languages mirror layouts and use suitable fonts.
  - Deep‑linked auth screens render in the chosen language.
- Candidate automated tests
  - `SettingsStorage` basic get/set/update
  - `LanguageManager.validateAndNormalize` (e.g., `"EN" -> "en"`, `"ar-EG" -> "ar"`, unsupported cases)
